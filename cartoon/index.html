Build plan

Five stops from scope to the app stores

Every step ends with something that runs on a real phone, so nothing is a surprise at launch.

  1. 1

    Scope

    Lock the feature list, local wallets, delivery zones, fees and commission rules.

    Outputa fixed feature list
  2. 2

    Design

    Figma screens for all four apps, clickable before any code is written.

    Outputclickable designs
  3. 3

    Build

    One Node.js API, Flutter apps for customers and riders, React for the website and dashboards.

    Outputa test build every week
  4. 4

    Payments and live features

    Card and wallet gateways, cash tracking, live rider maps, push, SMS and email.

    Outputtest orders, end to end
  5. 5

    Launch

    Testing with real restaurants, store release, deploy scripts and docs, then a period of fixes.

    Outputstore releases and docs
Tech stack

Fast, secure and easy to maintain

Common, well-supported tools that are easy to pick up and maintain.

Mobile apps

Flutter

One codebase for the Android and iOS customer and rider apps.

Website and dashboards

React

The customer website, the restaurant panel and the admin console.

Backend

Node.js + PostgreSQL

One API and one database for orders, payments, users and roles.

Live updates

WebSockets + Maps

Rider location, ETAs and order status update in real time.

Messages

Firebase, SMS, email

Push notifications at every step, receipts by SMS and email.

Hosting

AWS

Deploy scripts and autoscaling for the lunch and dinner rush.
